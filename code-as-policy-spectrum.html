流程流派 P1–P6 与场景定义（点击展开）
P1 单次生成：一次性生成即执行，无迭代；靠精心设计的 API/harness 约束正确性。替代“写初稿”。
P2 内环自纠：生成→执行→诊断→修订，固定预算；关键是失败归因。替代“改 bug”。
P3 进化搜索：养种群、并行评估、选择变异；人的品味被适应度+选择算子替代。替代“方案探索与取舍”。
P4 技能沉淀：优化目标是可复用库；验证过的代码成为资产摊销到未来任务。替代“经验积累与复用”。
P5 多智能体：把人的工作流角色拆成多个 agent 共享代码工件，或物理机队并行。替代“团队协作与评审”。
P6 蒸馏回灌：agent 生成的代码变成训练数据/教师去训模型，部署的是权重。替代“教学/数据标注”。
策略 Policy：代码即机器人/控制策略，运行时输出动作。
动作 Action：代码即通用 agent 的统一动作空间（GUI/OS/软件）。
奖励/训练 Reward：代码即奖励函数或训练管线。
技能 Skill：代码即可复用技能/库单元。
约束/监控 Constraint：代码即可执行的安全约束与监控。
世界 World：代码即世界模型/可执行世界表示。
设计/规约 Design（新增）：代码即设计产物——本体（语义设计）、CAD（几何设计）、前端（视觉设计）、法规（规范设计）。本体域自带免费形式化 L1（OWL 推理机/SHACL 校验器）。
推理/感知 Reasoning（新增）：代码即推理介质——程序化思维链、视觉程序、符号推理。
Agent/工作流自身 Agent-Self（新增）：代码即 agent 的架构与工作流本身——元层面：agent 写 agent。
科研/流程 Research：代码即科研与工程流程本身。

结构性认识

1. 对角线规律：每个场景有“本能”流程

策略的本能是 P2/P4/P6（真机反馈贵，靠自纠、沉淀、蒸馏摊销），奖励的本能是 P3（仿真便宜可大规模并行），世界的本能是 P2（渲染对齐信号天然构成反馈），动作的本能是 P2（符号反馈最便宜，可高频），科研与 Agent 自身的本能是 P3/P5（元层没有外部 oracle，靠搜索与互相评审）。场景的反馈成本结构决定了流程选择——这是矩阵隐含的经济规律。

2. 格子内部：反馈信息设计 > 流程拓扑

同为 P3 进化搜索，只喂适应度分数的 FunSearch/EoH 得 9.1/6.2 分，喂执行统计+失败模式+领域提示的 EvoEngineer 得 66.6 分——7 倍差距完全来自给 LLM 看什么诊断信息（arXiv 2601.06845 消融）。真正的竞争在反馈 oracle 的质量，不在环的形状。

3. P4（技能沉淀）实证基础最不牢

谱系可前移到 LLM 时代之前（DreamCoder wake-sleep 库学习，2020），但 2026 年出现系统性反弹：EACL 2026《Is This LLM Library Learning?》质疑库学习是否只是算力硬堆；《LLM Library Learning Fails: LEGO-Prover 案例研究》直接给出失败分析。

4. “代码 vs 权重”的定量边界

进化出的 59 行策略代码在成功率（70% vs PPO 60%）与可解释性上赢过 1 万个不透明参数，但平均奖励输（143.6 vs 214）。代码赢在可信与稀疏任务，权重赢在期望性能——这就是 P1–P5（部署代码）与 P6（蒸馏成权重）的分界线。

5. 第二轮补格浮出的两条元层暗线

其一，推理/感知行证明"代码即推理"（PAL/PoT/VisProg/ViperGPT）是全部流派的底层介质——它的 P6 格（VPD 视觉程序蒸馏）正是"代码推理→权重"的通用范式原型。其二，Agent/工作流自身行把 harness 综述里"harness 改进 harness"的开放问题变成了已有 4+ 篇 ICLR/ICML 工作的活跃前沿（ADAS/AFlow/GPTSwarm/EvoAgent）——自指环比预想的成熟得更早。

6. 补格过程观察到的"空白塌陷模式"

原空白格全部以近邻或混合形态先塌陷为半空白，且遵循同一顺序：语言空间先于代码空间（LATS/ReasoningBank 在语言空间先出现，代码形态仍空）、模块重组先于库检索（AgentSquare 的模块重组早于可检索的 agent 模式库）、多阶段管线先于对话式分工（SR-Platform 的四层管线先于多 agent 对话式建世界）、软件域先于机器人域（约束×P4 的库级不变式挖掘 Lisa/AssertMiner 先在软件域出现）、非 LLM 先于 LLM（奖励组合理论在经典 RL 已有，LLM 形态仍空）、蒸馏对象从行为升到架构（AgentDistill→AgentArk）。预测剩余 4 个真空白也会按此顺序被填：先出近邻，再出正主。

第三维：反馈栈（L0–L2）——同一生态位内的分级坐标

行和列回答“在哪里”，反馈栈回答“垒到了多高”。一个生态位的完整质量阶梯是三层：L0 证据构建（专用信号提取器——SAM3/VGGT/SAM3D 前处理、编译器回显、仿真训练曲线、真机遥测）决定环的噪声下限；L1 闭环验证（propose-execute-render-verify、单元测试、进化适应度）决定收敛速度；L2 资产飞轮（验证过的产物变成训练数据/技能库/改进配方）决定复利。典型即《Code as Worlds》的阶梯：

用验证过的 EWR 生产精确物理标注、训练 VLM（数据飞轮）★★★
  ↑ 由闭环发现保证质量（propose-execute-render-verify）★★
    ↑ 由证据构建提供约束（SAM3/VGGT-Omega/SAM3D 前处理）★

  • 同格分级：世界×P2 内 WorldCoder（★★ 只有交互验证）vs Code-as-Worlds（★★★ 全栈）；策略×P3 进化环都是 ★★，但没人把进化出的策略沉淀为库——所以该格升不到 ★★★，这正是隔壁 P4（ASPIRE ★★★）存在的原因。
  • 空白格 = 缺层：推理×P3 缺 L1（推理程序没有“渲染对比”等价物，验证信号只剩答案对错——太稀疏）；奖励×P4/P6 是 L1 在（Eureka 种群）、L2 未接线（进化出的奖励用完即弃）；约束×P6 是 L0/L1 在（CaM/Lisa）、L2 无。
  • L2 的合法性由 L1 保证：无验证的飞轮就是模型坍缩——有正式证明（Escaping Model Collapse via Synthetic Data Verification）；verifier 强于 generator 是飞轮可行的前提（verifier-generator gap、deliberate practice 缩放律、Weaver 弱验证器组合）。
  • 反例同样有信息量：RoboPro 是“飞轮在转但 L1 弱”（靠合成规模而非闭环验证保质量）；GenSwarm 是“无环直发”（★）。全矩阵里 ★★★ 的工作不足 1/5——L2 是稀缺资源。
  • 产业侧已把 L2 做成显学：数据飞轮正主见 策略×P6（VERITAS/DexFlyWheel/RPDF）与世界×P6（Cosmos 数据引擎，神经形态近邻）；“下一个护城河是数据飞轮”已成行业共识。

确认的研究空白（斜纹格，四轮检索+缺层分析）

  • 推理×P3：程序化推理的种群搜索——缺 L1：先要为推理程序造出“渲染对比”级的验证信号（中间步骤可执行检查？符号引擎裁决？），LATS/QDAIF 都因信号弱停在语言空间。
  • 奖励×P4：LLM 奖励片段库——L2 未接线：Eureka 的 L0（环境源码+训练曲线）与 L1（进化适应度）都在，验证过的奖励组件却无人沉淀复用；经典 RL 的组合奖励理论可当接口。
  • 奖励×P6：进化奖励→reward model 蒸馏——L2 未接线：Eureka 种群的最优奖励天然是 RM 训练数据，四轮检索仅见旁述。
  • 约束×P6：验证器蒸馏——缺 L2：L0（约束元素跟踪/断言挖掘）、L1（CaM/Lisa）已在软件与机器人域出现，把验证器蒸进权重的为零。
  • 设计×P3 / 设计×P4（新增行）：设计代码空间的种群进化（oracle 现成：渲染器+推理机，缺接线）；ODP 沉淀环——本体社区 2010s 的 Ontology Design Patterns 是现成技能库资产，Extended NeOn-GPT 停在“复用存量”，无人做“生成→验证→沉淀新模式”。本体域自带免费形式化 L1（OWL 推理机/SHACL 校验器），是比约束域更容易闭合的验证器库机会。
  • 结构性空白（4 格）：技能×P1/P2、Agent 自身×P1、科研×P1——定义上不可能有正主。
六轮周期表式补格累计收获：R1 建立 7×6 矩阵；R2 新增 2 行（推理/感知、Agent 自身）并修正 2 处 ID 错误；R3 填实世界×P5、Agent 自身×P6；R4 补入 ELM/RoboGen 并用近邻填掉 6 个空白；R5 新增第三维反馈栈+数据飞轮正主；R6 新增设计/规约行（本体×4、CAD×4、前端×1、SHACL×2 共 11 篇，全部核验）——本体线的“语法对但语义弱”发现与 ODP 沉淀环机会是该行的关键定位。文献 67→126 条（设计行含 1 条跨格），会话核验 27→75 篇。
